# CLS 2.0-dev1

**Versión**: 2.0.0-dev-1 · **Rama**: `releases` · **Fecha**: primera entrega de la serie 2.0

Este es el primer lanzamiento de la línea **2.0**. Al ser la primera versión de
esta serie, la comparación se hace únicamente contra sus antecesoras **1.1** y
**1.2** — no existe una 2.0 anterior con la que comparar.

---

## De dónde venimos: 1.1 y 1.2

### CLS 1.0–1.1
- Implementación original en **Python/Cython** (intérprete `ccls.py`, motor
  `clslang/`).
- Compilación lenta incluso para archivos pequeños; el propio proyecto lo
  reconocía como su principal problema.
- Proyecto en constante progreso, pero sin alcanzar un rendimiento aceptable
  para uso real.

### CLS 1.2
- "La versión del rendimiento": reescritura desde cero del motor para atacar los
  **tiempos de compilación**.
- Siguió siendo **Python/Cython**, con un ejecutable experimental (`ccls.py`,
  `main.pyx`).
- Etiquetada como **EXPERIMENTAL** y *no apta para proyectos*: era un prototipo
  del rendimiento, no una versión estable del lenguaje.

---

## Qué cambia en 2.0-dev1

La serie 2.0 **no es una evolución de 1.2**: es un **reescrito completo en
Rust** (workspace de 7 crates/nodos) con una arquitectura modular y un pipeline
orientado a WASM. Esto ataca de raíz los dos problemas que hundieron a 1.1/1.2:

| | 1.1 | 1.2 | **2.0-dev1** |
|---|---|---|---|
| **Implementación** | Python/Cython | Python/Cython | **Rust** |
| **Ejecución** | Intérprete (tree-walker) | Intérprete experimental | **Intérprete JIT** (CLS → WASM → wasmtime) + tree-walker deprecado |
| **Rendimiento** | Lento | Lento (prototipo) | **JIT/WASM**: fib 4391ms → 13ms, arrays 345ms → 0.7ms, math 80ms → 5ms |
| **Pipeline** | parse → ejecutar | parse → ejecutar | `.clsx` → lexer → parser → AST → **typeck** → **WASM** → wasmtime |
| **Tipado** | dinámico | dinámico | **type checker en compile-time** (`clx check`) |
| **Módulos** | imports básicos | imports básicos | **2 sistemas**: `import` (fuente) + `Lib.load` (`.clslib`) |
| **Estado** | hobby, lento | experimental | **apto para lanzamiento** (auditado) |

## Novedades destacadas frente a 1.1/1.2

- **Lenguaje**: OOP (clases, herencia, `super`, visibilidad `private/protected/public/static/readonly`),
  enums, tuplas, records tipados, alias de tipos, uniones, interfaces genéricas,
  genéricos, operador `is`, arrow functions, CMX (JSX nativo), async/await,
  try/catch/finally.
- **Backend WASM**: código WASM emitido por el compilador, ejecutado por
  wasmtime (JIT) o wasmi; internals precompilados fusionados dentro del módulo
  CLS (cero imports), shadow call stack en memoria lineal.
- **Sistema de errores**: trazo completo con call stack numerado + fuente, en
  formato extensible (Plain/Console/Html/Json).
- **Toolchain**: CLI `clx` (new, run, check, build, ast, repl, maptype, lsp, add,
  install), runtime ligero `clxr`, LSP server, extensión VS Code, bindings
  C/Python/JS (`clsb`).
- **Stdlib**: `math`, `json`, `fs`, `http`, `Lib` + métodos de primitivos sin
  boxing (dispatch tables estáticas).
- **Distribución**: portables por OS, binarios sueltos, extensión y bindings
  publicados automáticamente por este pipeline de CI al push a `releases`.
