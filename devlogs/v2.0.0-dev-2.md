# CLS 2.0-dev2

**Versión**: 2.0.0-dev-2 · **Rama**: `releases` · **Fecha**: segunda entrega de la serie 2.0

Segunda entrega de la serie 2.0. Dev-2 no cambia el lenguaje: **afina la
distribución**. La comparación se mantiene contra **1.1** y **1.2** (única serie
anterior), con el detalle en `v2.0.0-dev-1`.

---

## Qué cambia en 2.0-dev2

### CI de releases estabilizado (pipeline verde de punta a punta)

El pipeline que publica cada `v2.0.0-dev-N` quedó **verde completo**
(build win/linux + extensión + release):

- **`undefined symbol: __cls_alloc`**: el cdylib `cls-internals-wasm` enlazaba
  con `__cls_alloc` indefinido a propósito (lo resuelve el linker de fusión al
  `__alloc` del módulo CLS). Las toolchains nuevas de rust-lld rechazan símbolos
  indefinidos por defecto; el build script ahora pasa `--allow-undefined` vía
  `--config target.<triple>.rustflags`, limpiando las env vars de rustflags que
  el cargo padre inyecta (tienen prioridad sobre la config) — ver
  `cls-internals/build.rs`.
- **Empaquetado Linux**: `EXE_EXT` vacío es válido en Linux; se usa
  `"${2:-}"` en vez de `"${2:?}"`.
- **Ejecutables**: `scripts/*.sh` marcados `+x` (bit de ejecución) para el
  runner de Linux.
- **Release**: el publicador de GitHub re-corrido ante el 503 transitorio del
  servicio (infraestructura de GitHub, no del pipeline).

### Extensión VS Code como `.vsix` instalable

La extensión ya no se publica como zip plano: se empaqueta con **`vsce`** en un
**`.vsix` real** (`extension.vsixmanifest` + `[Content_Types].xml`):

- Instalable con `code --install-extension cls-lang-2.0.0.vsix` o desde
  "Extensions → … → Install from VSIX".
- **Lista para el VS Code Marketplace**: versión `2.0.0`, publisher `frask`,
  licencia MIT, repositorio y **icono** incluidos.
- `.vscodeignore` mantiene el paquete limpio (solo runtime).
