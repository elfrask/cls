# CLS 2.0-dev2

**Versión**: 2.0.0-dev-2 · **Rama**: `releases` · **Base**: `v2.0.0-dev-1`

Segunda entrega de la serie 2.0. Cambia el lenguaje y el runtime: cierra el FFI
estructurado, convierte **`JSON`/`Value`** en tipos de primera clase, habilita
los **módulos de usuario (clases incluidas) en el JIT**, reimplementa el framework
HTTP del lab sobre CLS puro + FFI, **elimina el tree-walker**, y —tras montar la
**fase de pruebas diferenciales**— incorpora **`match`** (pattern matching) y
completa el **tipado estático eliminando `Any`**. Se completa además el **rework
de CMX** (ahora una **clase core escrita en CLS**, construcción inline 0 host), el
**plan de pruebas diferenciales** (#1–#10) y el **desempaquetado de clases** con
`__destructurate()`. Se abre **`/cls-repositories`** como espacio de proyectos
reales (el primero es el framework de dev-2).

> Este documento consolida `devlogs/v2.0.0-dev-2.md.bak` (contenido previo) y lo
> actualiza al **estado actual del proyecto**: suites JIT **85+24 PASS**, `cargo
> test` **0 failed**, build **0 warnings**.

## Features

### 1. FFI estructurado sobre el layout canónico (`CRecord` / `CArray` / `CStruct`)

Las extensiones nativas ya no serializan a representaciones propias: leen y
escriben **el layout de memoria lineal del módulo** (el mismo de los hosts JIT),
con marshalling por tag.

- Tipos nativos nuevos en `ty_code`: `CRecord`(r) / `CArray`(a) / `CStruct`(S) —
  viajan como puntero al layout; `CDouble/CInt/CString/...` con letras propias
  (antes caían al default `'i'` y cranelift rechazaba firmas).
- El wrapper (`wasmtime_rt`/`wasmi_rt`) traduce offset-wasm ↔ dirección-host: la
  memoria lineal es una alocación del host, así el DLL opera el mismo layout en
  su espacio de direcciones.
- **Retorno con buffer propio**: si el DLL devuelve un malloc fuera de la memoria
  del módulo, el wrapper lo re-serializa re-mapeando keys/values string (offsets
  relativos `(off<<32)|len`) — antes solo in-place funcionaba.
- **`CStruct` como retorno**: `-> NombreDelStruct` con el `structure` declarado
  en la `extension`; el emisor registra los structs de extensión en `struct_defs`
  y el acceso a campos va por offsets (`p.x`, `p.y`).
- `CFloat` y aridad >4 documentados como límite con error claro.
- **Dispatcher FFI con `libffi`** (firma real por slot): corrige el paso de
  `CDouble` (antes llegaba por registro entero). Retorno `CString`
  byte-transparente vía `NativeRet::{Value,Bytes}`.
- Ejemplos + fuentes C de prueba en `examples/test/jit-examples/ffi-*`.

### 2. FFI de `structure`: layout ABI C

`structure` se alocaba con header CLS de 16B + campos en slots de 4/8B, y el FFI
le pasaba a la DLL el puntero al header → C leía basura (`sin_family` = `def_id`,
`sin_port` = 0 → puerto efímero).

- Layout **ABI C**: header 16B + data con ancho natural `i8/i16/i32/i64/f64`,
  alineación natural, total a 8; arrays inline `T[n]` (`i8[8]`, `i8[257]`).
- Los params struct del FFI reciben `base+16` (la data, sin header); el retorno
  struct lleva su tamaño total en el nombre del import (`S<bytes>`).
- Los errores de llamada nativa ya **no se silencian**; un local con nombre de
  builtin (`var len = ...`) ya no es sombreado por el handle del builtin.
- Documentado en `docs/lenguaje/estructuras.md` ("Layout en memoria") +
  `extension.md`/`jit.md`/`desarrollo/minilaravel.md`. Test `units/ffi-cstruct`
  (cross-OS, oráculo `getsockname` in-process).

### 3. JSON tipado: `JSON` y `Value` (sin `Any`)

El contrato público del JSON deja de usar `Any`:

- `Type::Json` / `Type::Value` representan los alias recursivos
  (`JSON = Record<String, Value | JSON | Value[]>`,
  `Value = String | Int | Float | Bool | JSON`): anotaciones parseables,
  asignables (`todo → Value`; `JSON/Record/Shape/Array → JSON`; primitivo
  **no** → JSON) y consultables con `is JSON` / `is Value`.
- `json.clsi`: `parse(text: String) -> JSON`, `stringify(value: Value) -> String`.
  Acceso `o.campo` / `o["k"]` / `arr[i]` tipa a `Value`; print/str/stringify/`==`
  despachan por **tag runtime** sin perder el tipo.
- `host_any_index` normaliza índice numérico vs clave string (los arrays
  top-level de `json.parse` son records con claves `"0","1",...`).

### 4. Módulos de usuario en el JIT (incluye clases)

Hasta dev-1 el JIT solo compilaba el entry point. Ahora aplana el grafo completo:

- `flatten.rs`: `push_export/push_prefixed/push_all` incluyen `ClassDecl`,
  `StructureDecl`, `InterfaceDecl`, `TypeAliasDecl` (antes solo fn/var/const/enum
  — `Clase(args)` daba "no soportado").
- **Aplanado transitivo**: cada módulo del grafo aporta sus exports (las clases
  importadas usan símbolos de sus propios imports); dedup por hash de
  declaraciones (módulos duplicados con igual contenido no se aplanan dos veces).
- Constructor namespaced `lib::Clase(args)` y estáticos namespaced
  `lib::Clase.campo`.

### 5. `match` (pattern matching, F1–F6) + enums con payload

`match` es una **expresión** (y sentencia) con 4 modos y un motor de matching
**unificado enum/clase**. Diseño completo en `agent-context/MATCH_PLAN.md`.

| Fase | Contenido |
|---|---|
| **F1** | Modos `is` (tipo), `in` (valor), `if` (condición) y sin-keyword (**patrón**). Binding `nombre <- expr`; **narrowing** por arma; `default` opcional; match vacío = error; tipo = 1ª arma. |
| **F2** | **Enums con payload** (`enum R { ok(String), err(int,String), s1 }`): construcción `R::ok(...)`, patrón declarativo `ok(x)`/`err(a,b)`, **destructuring-let** `var R::ok(v) = r;`; layout heap `[def_id][idx][arity][payload…]` (los unit-only siguen empacados i64). |
| **F3** | **`?:` estilo JS** + **`if` como expresión** (`if (c) { * <- a } else { * <- b }`). |
| **F4** | **`arrowReturn` `<-`** léxico: `*`/`**` (ternario: rama de `if`-expr o cuerpo de arma de `match`) y `match`/`match*` (match por conteo); atraviesa loops; sin target = error; **sin cross-function**. |
| **F5** | **Acceso a miembro sobre unión** (dispatch por `class_id`/`def_id`); unión temporal por arma del modo `is`. |
| **F6** | **Protocolo de clases**: `__match() -> E` (namespace = variantes de `E`) + `__unpack(tag)` (payload computado); `is` / `in`(`__equals`) / `if`(`__bool`). |

### 6. CMX como **clase core** (rework) + `Callable` + `is` + spreads

CMX pasó de "builtin con tablas hardcodeadas en el emisor" a una **clase core
`CMX` escrita en CLS** (`cls-core/src/frontend/builtins.rs`, inyectada en cada
módulo principal) respaldada por el builtin de 48 B. La lógica vive en los
métodos de la clase; el emisor hace **dispatch directo** `CMX::metodo(me, args)`
(CMX es final, sin vtable).

- **Campos** (`me.*` desde el builtin): `tag` (**siempre `String`**, también para
  tags mayúscula), `props: Record<String, Value>`, `children: Cmx[]`, `kind`
  (0=elemento, 1=texto), `tagCallable: Value`, `isComponent: Bool`.
- **Métodos (CLS)**: `isPrimitive()` (`!isComponent`), `isEmpty()`,
  `isElementOf(tag)`, `flattenChildren()`, `tryCallTag()` (invoca
  `tagCallable(props, children)` si es componente; `null` si no).
- **Métodos nativos**: `toString()`/`__str`/`__repr` (`__intr_cmx_fmt`) y
  `cloneWith(props?, children?)` (copia inmutable inline).
- **Construcción inline** (0 host): `__alloc(48)` + stores; `props` con
  `__intr_record_*`, `children` como pares `(val, tag)` stride 16. Se eliminaron
  los host fns `cmx_new/set_prop/add_child/to_string`.
- **Componentes (tag mayúscula)**: `tag` = nombre, `isComponent = true`,
  `tagCallable` = handle:

  ```clx
  if (app.isComponent) { app.tagCallable(app.props, app.children); }
  // equivalente: app.tryCallTag()   (null si no es componente)
  ```

- **`Cmx<P, PP>`** (anotación genérica) **borrada**: se acepta la sintaxis del
  spec y se ignora. `c is Cmx` funciona.
- **Sintaxis**: atributos desnudos (`disabled` → `true`), shorthand `{var}` (con
  el tag del tipo de la variable), spread `{...base}`, literales CMX anidados en
  `{...}`, keys de record/member con keywords (`{class: ...}`, `rec.method`).
- **`is` con narrowing**: `if (x is Tipo)` estrecha `x` dentro del bloque.
- **`Type::Callable`**: valor invocable (función simple, closure, objeto con
  `__call`); `Fun(..) → Callable`, anotable; en runtime se identifica por el
  **tag-bit del handle**.
- **Spreads**: records `{...base, c: 3}` (`__intr_record_merge`), arrays
  `[0, ...a, 4]`, props CMX `<App {...props} />`. Fix de write-back del ptr
  reallocado en `record_set`/`arr_push`/`merge`.
- **Dogfooding**: `examples/cmx-templates/src/engine.clsx` usa `match` (modo
  `in`) para `escape`, `isVoid` y `render`, en lugar de cadenas de `if/elif`.

### 15. Eliminación del tree-walker (Fase 7)

El tree-walker deprecado (`cls-runtime/src/walker/`) se eliminó por completo. El
JIT (`clx run`) es el único intérprete; `--ast-walker` se acepta pero se ignora
silenciosamente (compatibilidad de scripts).

- `Value` se movió a `cls-runtime/src/value.rs` (lo conserva el FFI nativo);
  `ImportFrame` a `cls-core/src/error.rs`.
- `nodos/clxr` y `subcommands/run.rs` reescritos a JIT-only; módulos del nodo sin
  consumidores eliminados (`os`, `path`, `process`, `random`, `time`).
- Los scripts de auditoría comparan JIT contra **oráculos `.expect`**.

### 16. Tipado estático: `Any` eliminado

- **`Any` como anotación**: eliminado. `var x: Any` → error ("usá un tipo concreto
  o `Value`/`JSON`/`Cmx`"). Fallout migrado a `Record<String, Value>` / `JSON` /
  `Value[]` (`.clsx`, `.clsi`, docs, grammar, tabla de tipos). Fixes de emisión
  necesarios: `toString()` sobre `Value`/`Json`, `length`/`size` de `JSON`.
- **`Type::Any` interno**: eliminado del `enum Type` (~180 sitios). Se usa
  **`Type::Value`** como **top universal** (equivalente: assignable en ambos
  sentidos, `was_type = I64`). `TypeKind::Any` se conserva **solo** para dar el
  error de anotación.
- Los "dinámicos tipados" son **`Value`**, **`JSON`** y **`Cmx`** (el tag runtime
  viaja con el valor).

### 17. Desempaquetado de clase con `__destructurate()`

`var Clase(a, b) = expr;` desempaqueta una instancia mediante un magic nuevo de
clase. Sustituye el camino anterior basado en offsets de campos por un contrato
explícito: la clase decide **cómo** se proyecta su payload.

- **Contrato**: `__destructurate() -> T | (T1, T2, …)`. **1 bind = valor único**;
  **N binds = tupla de aridad N**; `_` ignora un slot. El tipo de cada bind sale
  del retorno anotado (misma regla que `__unpack`).
- **Typeck**: exige que el nombre del patrón sea una clase conocida, que el valor
  sea de esa clase o subclase, y que el magic exista. La aridad del patrón debe
  coincidir con la forma del retorno anotado; si no, error estático.
- **Herencia**: el magic se resuelve subiendo por `ancestors` (el hijo puede
  overridearlo; si no, hereda el del padre).
- **Emisor**: `emit_destructure_class` llama `obj.__destructurate()` por vtable y
  liga los binds con `emit_payload_binds_from_value`, helper compartido con
  `__unpack` (valor único o tupla `[cap][len][slots*8]` + guard de aridad).
- **Tests**: positivo `units/destr-class.clsx` (construcción directa, variable,
  slot `_`, herencia con override) + negativos `destr-class-{arity,type,nomagic,
  notclass}` registrados en `run-tests.ps1`. `MPayload` de `lang-features` usa el
  magic.
- **Docs**: `docs/lenguaje/{control-de-flujo,sintaxis,magics,enums}.md`.
- `var Clase::variante(...)` (variantes computadas) sigue **fuera de alcance**:
  para eso se usa `match` con `__match`/`__unpack`.

## Correcciones

### Emisor JIT (framework HTTP end-to-end)

- **Arrows**: retorno inferido desde el type map del span del `return expr`.
- **Shape→hashmap en argumentos** (`emit_call_arg`): record literal contiguo
  pasado a parámetro dinámico (`Record/JSON/Value`) se emite como hashmap.
- Call de función almacenada en variable dinámica (`var f: Value = doble; f(21)`):
  `call_indirect` con firma universal.
- `coerce_to_bool` para valores dinámicos.
- Assignment a campo de Record dinámico `r.campo = val`.
- Dead-flow (`unreachable` + default de retorno).

### Bugs pre-existentes (Fase 7)

| Bug | Fix |
|---|---|
| `arr.toString()` vía host `ArrToString` (host no registrado) | Emisor usa `__intr_arr_to_string` |
| `Shape.has/keys/values` sin receiver | Emisor emite el objeto antes de llamar |
| Campo `Float` de un Shape leído como i64 crudo | `F64ReinterpretI64` tras `__intr_record_get` |
| `include` con exports del prelude re-definía | `pre_registered` + skip de re-definición |

### SKIP y fallbacks

- **8 SKIP de `units/`** resueltos (reescritos con `msvcrt.dll`/`libc.so.6`,
  args de app, validación por regex de red, `$expectedErrors`, oráculos).
- **Poda de fallbacks host→internals**: los `else { host.call(...) }` (código
  muerto inalcanzable) se eliminaron en ~30 sitios; `HostFn` podado de 130 a ~90
  variantes; **0 warnings** (antes ~20).

### Bytes de `String` (reporte del dev)

`from_utf8_lossy`/`&s[..]` corrompían; `s[i]` devolvía U+FFFD y `slice`/`indexOf`
eran incoherentes con `length`. Fix: `mem::read_bytes/write_bytes` crudo y
`strings.rs` **byte a byte**; paridad en host fallback. Tests `units/str-bytes`,
`units/str-methods`.

### Retrofit de features (§5.6) y regresiones asociadas

Al retrofitar los tests para usar el **lenguaje completo** aparecieron 5

| Bug | Fix |

### `match` y `Any` (cierre)

- **B1** (`match`): `if`-expr anidada → WASM inválido → emitir `unreachable` en
  rama divergente.
- **B2** (`match`): `match is`/conversiones sobre **unión de builtins** → rechazo
  estático claro.
- **F-18**: armas con `const` de distinto valor → `Type::join_compatible`
  (asignable en cualquier dirección **o** mismo tipo base, **sin ensanchar**).
- **Any**: eliminado como anotación y como variante interna (ver Feature 16).

### Rework de CMX (clase core + sintaxis)

| Bug | Fix |
|---|---|
| `bool()` sobre un método CMX tipado `Value` en el prelude emitía `any_to_bool` con operando `i32` (WASM inválido) | Pre-registrar las firmas de `CMX` en el typeck **antes** de chequear el prelude |
| Atributo desnudo (`<input disabled />`) no llegaba a `props` | Token `AttrBare` + `CmxAttribute{value: None}`; el emisor empuja `I32Const(1)` con tag `Bool` |
| Literal CMX dentro de `{expr}` no parseaba | Drenar **siempre** `cmx_buffer` en el lexer (children de un tag ya emitido) |
| Keys de record/member con keyword se guardaban con comillas (`'class'`, `rec.'method'`) | `Keyword::as_str()` (sin comillas) en `parse_record` y `expect_member_name` |
| Shorthand `{var}` perdía el tag (un `String` local se leía como int) | El typeck registra el tipo de la variable en `attr.span`; el emisor lo usa para el tag |

## Pendientes

- **Framework HTTP (minilaravel)**: especificación lista en
  `docs/desarrollo/minilaravel.md`. **Corrección retroactiva**: el framework HTTP
  end-to-end descrito en versiones previas de este devlog **no fue commiteado**;
  debe **reimplementarse** (plan `pendientes-conversacion-dev2.md`, Tarea 4). Los
  handlers deben anotar sus parámetros (`(req: Request) -> Response`) y
  **retornar** el `Response` (un handler `void` responde 404 por defecto).
  Se desarrolla en **`cls-repositories/framework/`** (ver Feature 18).
  *Ya commiteados*: los fixes de emisor asociados (arrows, `emit_call_arg`,
  FunValue dinámica, coerce a bool, `r.campo = val`).
- **Reportes de cierre #7–#10**: faltan en `examples/reportes/` los de
  `cmx-templates`, `pkgcheck`, `snake` y `scheme` (regla §5.5: regresiones +
  soluciones + veredicto del Juez).
- **Spread restante** (`REST_SPREAD_PLAN`): rest params `function f(...nums)`,
  spread en calls `f(1, ...args)`, spread en tuplas. El `call_indirect` exige
  arity estática — los rest params requieren cambio de ABI (`__rest`).
- **Namespaced `import as` + clases**: mapear nombre real ↔ prefijado dentro de
  métodos (`me.campo` sobre clases flatteneadas como `lib::Clase`).
- **SSO de strings** (small string optimization): handoff
  `agent-context/plan-performance/HANDOFF-STRING-SSO.md` — aprobada con la
  condición de no empeorar el rendimiento (materialización FFI aceptable).
- **Caso de borde de serialización**: una **clase como atributo directo de CMX**
  (`<html ref={carlos} />`) se guarda como `< />` (el type map del span queda
  `Cmx`); el mismo valor vía spread o como prop de record sí serializa.
  Investigado, sin fix aislado.
- **Identificador local `path`**: `path.miembro` se parsea como namespace del
  módulo interno `path` aunque `path` sea un parámetro/local (typeck resuelve el
  scope después, pero el AST ya es `NamespaceAccess`). Mitigación en tombstone:
  el parámetro se llama `route_path`. Pendiente: parser consciente de scope.
- **Flatten de exports hermanos**: si un módulo exporta una clase que llama a
  otra función exportada del mismo módulo y el consumidor no la importa
  explícitamente, `flatten` no la transporta y la llamada usa un handle sin
  inicializar (trap `indirect call type mismatch`). Mitigación: el barrel
  importa todos los símbolos hermanos. Pendiente: incluir dependencias
  exportadas del módulo.
- **GAPs de la matriz de features** (`examples/lang-features/findings/`):
  - **06** — índice dinámico de tupla heterogénea (requiere boxing).
  - **17** — `module`/`namespace` sin cablear.
  - **19** — `Value` **local** no taggeado (preexistente); el camino soportado es
    leer de un `Record`/`JSON`.
