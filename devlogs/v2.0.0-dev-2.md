# CLS 2.0-dev2

**Versión**: 2.0.0-dev-2 · **Rama**: `releases` · **Fecha**: segunda entrega de la serie 2.0

Segunda entrega de la serie 2.0. Comparación contra **`v2.0.0-dev-1`**
(`git diff releases..master`, 64 archivos). Dev-2 sí cambia el lenguaje y el
runtime: cierra el FFI estructurado, tipa el JSON, habilita los módulos de
usuario en el JIT (clases incluidas) y deja el framework HTTP del lab
sirviendo end-to-end. Además de la distribución (CI + `.vsix`).

---

## Qué cambia en 2.0-dev2

### FFI estructurado sobre el layout canónico (`CRecord` / `CArray` / `CStruct`)

Las extensiones nativas ya no serializan a representaciones propias: leen y
escriben **el layout de memoria lineal del módulo** (el mismo de los hosts
JIT), con marshalling por tag:

- Tipos nativos nuevos en `ty_code`: `CRecord`(r) / `CArray`(a) /
  `CStruct`(S) — viajan como puntero al layout; `CDouble/CInt/CString/...`
  con letras propias (antes caían al default `'i'` y cranelift rechazaba
  firmas).
- El wrapper (`wasmtime_rt`/`wasmi_rt`) traduce offset-wasm ↔ dirección-host:
  la memoria lineal es una alocación del host, así el DLL opera el mismo
  layout en su espacio de direcciones.
- **Retorno con buffer propio**: si el DLL devuelve un malloc fuera de la
  memoria del módulo, el wrapper lo re-serializa re-mapeando keys/values
  string (offsets relativos `(off<<32)|len`) — antes solo in-place funcionaba.
- **`CStruct` como retorno**: `-> NombreDelStruct` con el `structure`
  declarado en la `extension`; el emisor registra los structs de extensión en
  `struct_defs` y el acceso a campos va por offsets (`p.x`, `p.y`).
- `CFloat` y aridad >4 documentados como límite con error claro.
- Ejemplos + fuentes C de prueba en `examples/jit-examples/ffi-*`.

### Módulos internos nuevos: `net` y `strings`

- **`net`** (sockets TCP): `listen/accept/recv/send/close/lastError`.
  Walker (`nodos/clx/src/modules/net.rs`), clsi y registro completo; hosts con
  `OnceLock` para los maps estáticos y `try_clone()` de sockets.
- **`strings`** (utilidades por bytes): `indexOf/slice/split`. Implementadas
  como **internals fusionadas** (`__intr_str_index_of/_slice/_split`): el WAT
  resultante hace **0 calls** a imports `str_*` — el parseo HTTP no cruza el
  límite WASM→host.

### JSON tipado: `JSON` y `Value` como tipos de primera clase

El contrato público del JSON deja de usar `Any`:

- `Type::Json` / `Type::Value` (representan los alias recursivos
  `JSON = Record<String, Value | JSON | Value[]>` y
  `Value = String | Int | Float | Bool | JSON`): anotaciones parseables,
  asignables (`todo → Value`; `JSON/Record/Shape/Array → JSON`; primitivo
  NO → JSON) y consultables con `is JSON` / `is Value`.
- `json.clsi`: `parse(text: String) -> JSON`,
  `stringify(value: Value) -> String`. Acceso `o.campo` / `o["k"]` / `arr[i]`
  tipa a `Value`; print/str/stringify/`==` despachan por tag runtime sin
  perder el tipo.
- `host_any_index` normaliza índice numérico vs clave string (los arrays
  top-level de `json.parse` son records con claves `"0","1",...`).

### Módulos de usuario en el JIT (incluye clases)

Hasta dev-1 el JIT solo compilaba el entry point. Ahora aplana el grafo
completo:

- `flatten.rs`: `push_export/push_prefixed/push_all` incluyen `ClassDecl`,
  `StructureDecl`, `InterfaceDecl`, `TypeAliasDecl` (antes solo
  fn/var/const/enum — `Clase(args)` daba "no soportado").
- **Aplanado transitivo**: cada módulo del grafo aporta sus exports (las
  clases importadas usan símbolos de sus propios imports); dedup por hash de
  declaraciones (módulos duplicados en FS con igual contenido no se aplanan
  dos veces).
- Constructor namespaced `lib::Clase(args)` (helper extraído, compartido con
  `Identifier`) y estáticos namespaced `lib::Clase.campo`.
- Campo `Any` en clase/struct compila (i64 + dispatch por tag en runtime).

### Sistema de declaraciones (directivas de diseño)

- **Declaración múltiple** top-level → error (colisión entre módulos
  importados o redefinición en el script). Pre-pasada de firmas marcada como
  `pre_registered` para no contar la re-definición del mismo símbolo.
- **Intrinsics core constantes**: `print/input/args/toString/int/float/str/
  bool/len/type/now/exit/sleep/throw` no redefinibles.
- Variables duplicadas en el mismo scope → error.
- Import alias repetido para el MISMO path entre módulos del prelude no es
  colisión (p.ej. `import "strings" as strings` en router y request).

### Correcciones del emisor JIT (framework HTTP end-to-end)

- **Arrows**: retorno inferido desde el type map del span del `return expr`
  cuando el span de la arrow es degenerado — antes caían a `Void`, se
  registraban con firma `-> ()` y el call dinámico trapeaba
  `indirect call type mismatch`.
- **Shape→hashmap en argumentos** (`emit_call_arg`): un record literal
  contiguo pasado a parámetro dinámico (`Record/JSON/Value/Any`) se emite como
  hashmap — antes `res.json({ok:true})` serializaba `{}` o trapeaba OOB.
  Conectado en fn top-level, `x::f()`, call dinámico Any (ambas ramas) y
  dispatch de métodos por vtable.
- Call de función almacenada en variable dinámica (`var f: Any = doble;
  f(21)`): call_indirect con firma universal `[capturas, i64...N] -> i64`;
  el tag-bit del handle decide closure vs función simple.
- `coerce_to_bool` para valores dinámicos (`host_any_to_bool`: int/float≠0,
  string len≠0, container len≠0, null→false).
- Assignment a campo de Record dinámico `r.campo = val` (antes solo
  `r["key"] = val`), extendiendo a i64 ANTES del LocalSet.
- Dead-flow (desde pre-release, incluido aquí si venía pendiente en la rama).

### Eliminación del tree-walker (Fase 7)

El **tree-walker deprecado** (`cls-runtime/src/walker/`) se eliminó por
completo. El JIT (`clx run`) es el único intérprete; `--ast-walker` se acepta
pero se ignora silenciosamente (compatibilidad de scripts).

- `Value` se movió a `cls-runtime/src/value.rs` (lo conserva el FFI nativo);
  `ImportFrame` a `cls-core/src/error.rs`.
- `nodos/clxr` y `nodos/clx/src/subcommands/run.rs` reescritos a JIT-only.
- Módulos del nodo sin consumidores eliminados: `os`, `path`, `process`,
  `random`, `time` (los hosts se registran por nombre literal en el runtime,
  no vía `module()`).
- Los scripts de auditoría comparan JIT contra **oracles `.expect`** (no contra
  el walker).

### Poda de fallbacks host a internals (Fase 8)

Las operaciones de strings/arrays/records/math/parse ya se resolvían a
internals fusionadas `__intr_*` (0 cruces WASM↔host); los fallbacks
`host.call(HostFn::X)` eran **código muerto inalcanzable** (la fusión es
incondicional). Se eliminaron:

- `else { host.call(...) }` en ~30 sitios del emisor (quedan solo los `Call` a
  internals).
- `emit_str_host` perdió el 2º param (HostFn) y el fallback.
- Enum `HostFn` podado de 130 a ~90 variantes (solo lo que el emisor llama
  directo: I/O, reloj, closures, CMX, Any, JSON, módulos del nodo).
- Registros muertos en los runtimes (`str_eq`, `str_concat_slack`,
  `str_append`, `any_to_string`).

**Resultado**: `cargo build --workspace` con 0 warnings (antes ~20).

### Benchmarks actualizados (post-internals)

El reporte (`examples/audit/benchmark-langs/REPORTE-BENCHMARKS.md`) decía que
arrays/strings/math/calls eran host calls. Con las internals fusionadas, los
números mejoraron drásticamente:

| Prueba | Antes (15-ago) | Hoy | Mejora |
|---|---|---|---|
| Fib(30) | 4 391 ms | **17 ms** | x258 |
| Arrays (100k) | 344.7 ms | **1 ms** | x345 |
| Strings (10k) | 52 ms | **1 ms** | x52 |

| Llamadas (1M) | 1 918.7 ms | **4 ms** | x480 |

x2-130 más rápido que Python. Startup JIT: ~83 ms miss / ~76 ms cacheado.

### Tipo `Cmx` de primera clase

`Type::Cmx` se completó (réplica del patrón del tipo `JSON`):

- Member access tipado: `.tag → Value`, `.props → Record<String, Value>`,
  `.children → Array<Cmx>`, **`.kind → Int`** (nuevo: 0=elemento, 1=texto —
  offset 24 del layout, 0 host nuevo), `toString → String`.
- Asignable a `Value` y a los tipos de lectura (el tag runtime decide); NO a
  `Callable`. Anotable `Cmx`/`cmx`/`CMX`.
- `app.tag(...)` permitido (retorno `Value`).

### Tipo `Callable` + `is` con narrowing + spreads

Para invocar componentes CMX de tag mayúscula desde CLS:

```clx
if (app.tag is Callable) {
    app.tag({...app.props, children: app.children});
}
```

- **`Type::Callable`**: "valor invocable" (función simple, closure, objeto con
  `__call`). `Fun(..) → Callable`; anotable. En runtime se identifica por el
  **tag-bit del handle** (`v != 0 && v>>32 == 0` — el mismo predicado que
  `print` usa para `<function X>`).
- **`is` con narrowing**: `if (x is Tipo)` estrecha `x` dentro del bloque
  (scope anidado, se restaura al salir). `x is Callable` chequea el tag-bit en
  runtime.
- **Spread en records** `{...base, c: 3}`: `RecordExpr.spreads` + internals
  `__intr_record_merge` (Fase 2 de REST_SPREAD_PLAN).
- **Spread en arrays** `[0, ...a, 4]`: `Expression::Spread` + construcción con
  `__intr_arr_push` (loop dinámico con write-back del ptr que realloca).
- **Spread de props en CMX** `<App {...props} />`: `CmxToken::AttrSpread` +
  merge a las props del CmxValue (requiere source `Record<String, any>`).
- Fix de un bug latente: `record_set`/`arr_push`/`merge` reallocan y el ptr
  local quedaba inválido — write-back del ptr retornado en el emisor
  (síntoma: `c: 0` en `{a:1,b:2,...c:3}`).

Pendiente de spread: rest params `function f(...nums)`, spread en calls
`f(1, ...args)`, tuplas (el `call_indirect` exige arity estática — ver
`REST_SPREAD_PLAN.md`).

## Pendiente conocido (para dev-3)

- Reportador de errores del JIT: ante módulo inválido/trap vuelca bytes crudos
  de memoria/tabla; debe imprimir diagnóstico legible (function+offset + WAT
  vía wasmprinter). **Hecho en dev-2** (paso 4 de strings): diagnóstico corto
  + WAT detrás de `CLS_DUMP_WAT=1`.
- Optimización de strings: append in-place con header de capacidad oculto +
  fast path de interning en records (hecho en dev-2, ver abajo). SSO
  (small string optimization) queda como handoff propio:
  `agent-context/plan-performance/HANDOFF-STRING-SSO.md` — aprobada con la
  condición de que el rendimiento no empeore (materialización FFI aceptable).
- Namespaced `import as` + clases: mapear nombre real ↔ prefijado dentro de
  métodos (`me.campo` sobre clases flatteneadas como `lib::Clase`).
- **Spread restante** (de REST_SPREAD_PLAN): rest params `function f(...nums)`,
  spread en calls `f(1, ...args)`, spread en tuplas. El `call_indirect` exige
  arity estática — los rest params requieren un cambio de ABI (`__rest`).
- **Framework HTTP (minilaravel)**: especificación lista en
  `docs/desarrollo/minilaravel.md`; la implementación se delega a otro dev.
- **Bug de serialización**: `record_to_string` imprime mal los arrays anidados
  en records (el dato es correcto al leerlo de vuelta; es solo el formato).
