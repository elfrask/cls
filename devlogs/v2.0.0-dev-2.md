# CLS 2.0-dev2

**Versión**: 2.0.0-dev-2 · **Rama**: `releases` · **Fecha**: segunda entrega de la serie 2.0

Segunda entrega de la serie 2.0. Comparación contra **`v2.0.0-dev-1`**
(`git diff releases..master`, 64 archivos). Dev-2 sí cambia el lenguaje y el
runtime: cierra el FFI estructurado, tipa el JSON, habilita los módulos de
usuario en el JIT (clases incluidas) y deja el framework HTTP del lab
sirviendo end-to-end. Además de la distribución (CI + `.vsix`).

---

## Qué cambia en 2.0-dev2

### FFI estructurado sobre el layout canónico (`CRecord` / `CArray` / `CStruct`)

Las extensiones nativas ya no serializan a representaciones propias: leen y
escriben **el layout de memoria lineal del módulo** (el mismo de los hosts
JIT), con marshalling por tag:

- Tipos nativos nuevos en `ty_code`: `CRecord`(r) / `CArray`(a) /
  `CStruct`(S) — viajan como puntero al layout; `CDouble/CInt/CString/...`
  con letras propias (antes caían al default `'i'` y cranelift rechazaba
  firmas).
- El wrapper (`wasmtime_rt`/`wasmi_rt`) traduce offset-wasm ↔ dirección-host:
  la memoria lineal es una alocación del host, así el DLL opera el mismo
  layout en su espacio de direcciones.
- **Retorno con buffer propio**: si el DLL devuelve un malloc fuera de la
  memoria del módulo, el wrapper lo re-serializa re-mapeando keys/values
  string (offsets relativos `(off<<32)|len`) — antes solo in-place funcionaba.
- **`CStruct` como retorno**: `-> NombreDelStruct` con el `structure`
  declarado en la `extension`; el emisor registra los structs de extensión en
  `struct_defs` y el acceso a campos va por offsets (`p.x`, `p.y`).
- `CFloat` y aridad >4 documentados como límite con error claro.
- Ejemplos + fuentes C de prueba en `examples/test/jit-examples/ffi-*`.

### Módulos internos nuevos: `net` y `strings`

- **`net`** (sockets TCP): `listen/accept/recv/send/close/lastError`.
  Walker (`nodos/clx/src/modules/net.rs`), clsi y registro completo; hosts con
  `OnceLock` para los maps estáticos y `try_clone()` de sockets.
- **`strings`** (utilidades por bytes): `indexOf/slice/split`. Implementadas
  como **internals fusionadas** (`__intr_str_index_of/_slice/_split`): el WAT
  resultante hace **0 calls** a imports `str_*` — el parseo HTTP no cruza el
  límite WASM→host.

### JSON tipado: `JSON` y `Value` como tipos de primera clase

El contrato público del JSON deja de usar `Any`:

- `Type::Json` / `Type::Value` (representan los alias recursivos
  `JSON = Record<String, Value | JSON | Value[]>` y
  `Value = String | Int | Float | Bool | JSON`): anotaciones parseables,
  asignables (`todo → Value`; `JSON/Record/Shape/Array → JSON`; primitivo
  NO → JSON) y consultables con `is JSON` / `is Value`.
- `json.clsi`: `parse(text: String) -> JSON`,
  `stringify(value: Value) -> String`. Acceso `o.campo` / `o["k"]` / `arr[i]`
  tipa a `Value`; print/str/stringify/`==` despachan por tag runtime sin
  perder el tipo.
- `host_any_index` normaliza índice numérico vs clave string (los arrays
  top-level de `json.parse` son records con claves `"0","1",...`).

### Módulos de usuario en el JIT (incluye clases)

Hasta dev-1 el JIT solo compilaba el entry point. Ahora aplana el grafo
completo:

- `flatten.rs`: `push_export/push_prefixed/push_all` incluyen `ClassDecl`,
  `StructureDecl`, `InterfaceDecl`, `TypeAliasDecl` (antes solo
  fn/var/const/enum — `Clase(args)` daba "no soportado").
- **Aplanado transitivo**: cada módulo del grafo aporta sus exports (las
  clases importadas usan símbolos de sus propios imports); dedup por hash de
  declaraciones (módulos duplicados en FS con igual contenido no se aplanan
  dos veces).
- Constructor namespaced `lib::Clase(args)` (helper extraído, compartido con
  `Identifier`) y estáticos namespaced `lib::Clase.campo`.
- Campo `Any` en clase/struct compila (i64 + dispatch por tag en runtime).

### Sistema de declaraciones (directivas de diseño)

- **Declaración múltiple** top-level → error (colisión entre módulos
  importados o redefinición en el script). Pre-pasada de firmas marcada como
  `pre_registered` para no contar la re-definición del mismo símbolo.
- **Intrinsics core constantes**: `print/input/args/toString/int/float/str/
  bool/len/type/now/exit/sleep/throw` no redefinibles.
- Variables duplicadas en el mismo scope → error.
- Import alias repetido para el MISMO path entre módulos del prelude no es
  colisión (p.ej. `import "strings" as strings` en router y request).

### Correcciones del emisor JIT (framework HTTP end-to-end)

- **Arrows**: retorno inferido desde el type map del span del `return expr`
  cuando el span de la arrow es degenerado — antes caían a `Void`, se
  registraban con firma `-> ()` y el call dinámico trapeaba
  `indirect call type mismatch`.
- **Shape→hashmap en argumentos** (`emit_call_arg`): un record literal
  contiguo pasado a parámetro dinámico (`Record/JSON/Value/Any`) se emite como
  hashmap — antes `res.json({ok:true})` serializaba `{}` o trapeaba OOB.
  Conectado en fn top-level, `x::f()`, call dinámico Any (ambas ramas) y
  dispatch de métodos por vtable.
- Call de función almacenada en variable dinámica (`var f: Any = doble;
  f(21)`): call_indirect con firma universal `[capturas, i64...N] -> i64`;
  el tag-bit del handle decide closure vs función simple.
- `coerce_to_bool` para valores dinámicos (`host_any_to_bool`: int/float≠0,
  string len≠0, container len≠0, null→false).
- Assignment a campo de Record dinámico `r.campo = val` (antes solo
  `r["key"] = val`), extendiendo a i64 ANTES del LocalSet.
- Dead-flow (desde pre-release, incluido aquí si venía pendiente en la rama).

### Eliminación del tree-walker (Fase 7)

El **tree-walker deprecado** (`cls-runtime/src/walker/`) se eliminó por
completo. El JIT (`clx run`) es el único intérprete; `--ast-walker` se acepta
pero se ignora silenciosamente (compatibilidad de scripts).

- `Value` se movió a `cls-runtime/src/value.rs` (lo conserva el FFI nativo);

- Módulos del nodo sin consumidores eliminados: `os`, `path`, `process`,
  `random`, `time` (los hosts se registran por nombre literal en el runtime,
  no vía `module()`).
- Los scripts de auditoría comparan JIT contra **oracles `.expect`** (no contra
  el walker).

### Poda de fallbacks host a internals (Fase 8)

Las operaciones de strings/arrays/records/math/parse ya se resolvían a
internals fusionadas `__intr_*` (0 cruces WASM↔host); los fallbacks
`host.call(HostFn::X)` eran **código muerto inalcanzable** (la fusión es
incondicional). Se eliminaron:

- `else { host.call(...) }` en ~30 sitios del emisor (quedan solo los `Call` a
  internals).
- `emit_str_host` perdió el 2º param (HostFn) y el fallback.
- Enum `HostFn` podado de 130 a ~90 variantes (solo lo que el emisor llama
  directo: I/O, reloj, closures, CMX, Any, JSON, módulos del nodo).
- Registros muertos en los runtimes (`str_eq`, `str_concat_slack`,
  `str_append`, `any_to_string`).

**Resultado**: `cargo build --workspace` con 0 warnings (antes ~20).

### Tipo `Cmx` de primera clase

`Type::Cmx` se completó (réplica del patrón del tipo `JSON`):

- Member access tipado: `.tag → Value`, `.props → Record<String, Value>`,
  `.children → Array<Cmx>`, **`.kind → Int`** (nuevo: 0=elemento, 1=texto —
  offset 24 del layout, 0 host nuevo), `toString → String`.
- Asignable a `Value` y a los tipos de lectura (el tag runtime decide); NO a
  `Callable`. Anotable `Cmx`/`cmx`/`CMX`.
- `app.tag(...)` permitido (retorno `Value`).

### Tipo `Callable` + `is` con narrowing + spreads

Para invocar componentes CMX de tag mayúscula desde CLS:

```clx
if (app.tag is Callable) {
    app.tag({...app.props, children: app.children});
}
```

- **`Type::Callable`**: "valor invocable" (función simple, closure, objeto con
  `__call`). `Fun(..) → Callable`; anotable. En runtime se identifica por el
  **tag-bit del handle** (`v != 0 && v>>32 == 0` — el mismo predicado que
  `print` usa para `<function X>`).
- **`is` con narrowing**: `if (x is Tipo)` estrecha `x` dentro del bloque
  (scope anidado, se restaura al salir). `x is Callable` chequea el tag-bit en
  runtime.
- **Spread en records** `{...base, c: 3}`: `RecordExpr.spreads` + internals
  `__intr_record_merge` (Fase 2 de REST_SPREAD_PLAN).
- **Spread en arrays** `[0, ...a, 4]`: `Expression::Spread` + construcción con
  `__intr_arr_push` (loop dinámico con write-back del ptr que realloca).
- **Spread de props en CMX** `<App {...props} />`: `CmxToken::AttrSpread` +
  merge a las props del CmxValue (requiere source `Record<String, any>`).
- Fix de un bug latente: `record_set`/`arr_push`/`merge` reallocan y el ptr
  local quedaba inválido — write-back del ptr retornado en el emisor
  (síntoma: `c: 0` en `{a:1,b:2,...c:3}`).

Pendiente de spread: rest params `function f(...nums)`, spread en calls
`f(1, ...args)`, tuplas (el `call_indirect` exige arity estática — ver
`REST_SPREAD_PLAN.md`).

### Serialización recursiva de tipos compuestos (sin punteros en prints)

Cierre del bug de la dev-2 (test de estrés `examples/dev-2/completo.clsx` con
structs/clases/enums/tuplas anidados en records/props CMX): **ninguna
impresión muestra punteros**. Commits `7338a34` → `f35e2df`.

- **Print directo recursivo** (`emitter/print.rs` + `strings.rs`): helpers
  `emit_typed_value_to_string` / `emit_class_to_string` / `emit_enum_to_string`;
  `print(carlos)` serializa los campos anidados (`celulaMadre: Celula { id:
  101, ... }` en vez del ptr). Enum → nombre de la variante.
- **`str()`/`toString()` de clase y enum**: el fallback sin magic method era
  `__intr_str_int` (ptr); ahora cae a `emit_class_to_string`
  (`<Organismo {...}>`). Ramas nuevas para enums.
- **Fix bool**: structs/clases con campos `bool` (i32 en WASM) generaban WASM
  inválido al serializar (`expected i64, found i32`) — dispatch por el tipo del
  campo (`__intr_str_bool` para bool).
- **Valores Named en records dinámicos**: al guardar un struct/clase/enum en
  un record/props CMX (vía `emit_record_hashmap`/`emit_cmx`), el emisor lo
  **serializa a string** en el punto de guardado — el formateador genérico
  (`fmt.rs`) no conoce los tipos del programa.
- **Arrays de contenedores**: `[c1, c2]` / `[Estado...]` / `[{e: ...}]` se
  serializan completos con el loop `emit_named_array_to_string` (antes: ptrs
  por elemento).
- **Tuplas con `()`** (no `[]`): las tuplas comparten layout con los arrays y
  el formateo genérico las mostraba `[a, b]`; ahora se serializan a string al
  entrar a un contenedor con su formato `(a, b)`.
- **Tag RAW (9)**: los valores serializados se guardan con un tag propio que
  el formateador imprime **sin comillas** (el tag 1 de string ponía
  `"(10, 20)"` con comillas dentro de records). Los contenedores muestran
  `{coordenadas: (10, 20), lider: <Organismo {...}>}`.
- **Nota de caché**: varios de estos fixes parecían "no funcionar" hasta
  `clx clean` — el caché CLS→WASM viejo (compilado con un emisor anterior)
  enmascaraba los cambios. Verificación estándar: rebuild + `clx clean` +
  rerun.
- Oracle de `units/bug-cmx-array-tags.expect` regenerado (output mejorado).

### FFI de `structure`: layout ABI C + `CStruct` recibe la data (reporte del dev)

El dev del framework HTTP reportó que `bind`/`listen` devolvían 0 pero el
socket no escuchaba en el puerto pedido (`netstat` no lo mostraba). **Era un
bug del lenguaje**, no de la librería ni de su código:

- Los `structure` se alocaban con header CLS de 16B + campos en **slots de
  4/8B**, y el FFI le pasaba a la DLL el puntero al **header**. C leía
  `sin_family` = `def_id` (su "hay que declarar dos estructuras para que bind
  funcione" era el `def_id = 2` = `AF_INET` por casualidad) y `sin_port` = 0
  → el socket quedaba en un **puerto efímero** (reproducido: `0.0.0.0:52084`
  en vez de `9999`).
- Fix: layout **ABI C** en las `structure` (header 16B + data con ancho
  natural i8/i16/i32/i64/f64, alineación natural, total a 8) con arrays
  inline `T[n]` (`i8[8]`, `i8[257]` de `WSADATA`); campos con su ancho C en
  ctor/lectura/escritura/toString; y los params struct del FFI reciben
  `base+16` (la data, sin el header). El retorno struct ahora lleva su tamaño
  total en el nombre del import (`S<bytes>`).
- Los errores de llamada nativa ya **no se silencian** (antes CLS recibía 0
  sin explicación), y un local llamado como un builtin (`var len = ...`) ya no
  es sombreado por el handle del builtin (`emit_ident_load`).
- Documentado en `docs/lenguaje/estructuras.md` ("Layout en memoria") +
  `extension.md`/`jit.md`/`desarrollo/minilaravel.md` (bloque de socket).
- Test: `units/ffi-cstruct.clsx` (cross-OS; oráculo con `getsockname`
  in-process, sin red). Verificado además con `netstat`: `0.0.0.0:9999
  LISTENING`.

### Semántica de bytes de `String` (reporte del dev) + métodos intrínsecos

Los strings mezclaban UTF-8 con semántica de bytes: el internals decodificaba
con `from_utf8_lossy` y `slice` usaba `&s[..]` (panica en frontera no-char).
Síntomas: `s[i]` devolvía **U+FFFD**, recorrer byte a byte corrompía el UTF-8, y
`slice`/`indexOf` eran incoherentes con `length` (reporte del dev:
`2026-10-13-string-index-ufffd-no-ascii`). Fix:

- `mem::read_bytes`/`write_bytes` (crudo, sin UTF-8) y `strings.rs` byte-a-byte
  (`concat`/`_slack`/`append`/`length`/`indexOf`/`slice`/`split`/`contains`/
  `startsWith`/`endsWith`). Paridad en el host fallback (wasmtime/wasmi/clxb).
- **Métodos de `String`** intrínsecos (sin importar `strings`): `.split(sep)`,
  `.slice(a,b)`, `.indexOf(x)` (typeck + emitter, con validación de aridad).
- Tests: `units/str-bytes`, `units/str-methods`.

### Alias de módulos internos (`import "math" as m`)

No funcionaba: el emisor despachaba por el nombre **literal** del módulo. Ahora
`Engine.import_aliases` + `FuncEmitter.import_aliases` resuelven el alias en
typeck (`member`/`calls`) y emitter (`primitives`, `module_call_ret`,
`math.PI`/`E`); el `flatten` preserva los `import` de módulos internos. Tests:
`units/mod-alias.clsx`.

### `Cmx → String`: el tag como String (handle de componente → `""`)

`emit_coerce` era un **no-op**: `var tag: String = cmx.tag` guardaba el handle
crudo (`table_idx<<1`, p.ej. `126`) en vez de `""` para un componente, y
`var s: String = cmx` guardaba el puntero. Un renderer CLS que detecta
componentes con `tag.length == 0` tomaba la rama equivocada (los iconos CMX se
perdían: `< name="logo"></>`). Fix en `emitter/containers.rs`: destino `String`
desde Cmx emite el tag y convierte un handle de función
(`if (tag>>32)==0 {0} else {tag}`). No afecta a tags String normales.

### Gestor de paquetes (Fase A), subcomandos y registry

- **`clx install`**: todo paquete va al store **global versionado**
  (`~/.cls/modules/[scope/]nombre@versión/`); rechaza sin `name`/`version`
  (semver) y sin `export.entry`; `--save` registra la dep exacta. Se quitó
  `-g/--global` (todo es global). `./modules/` queda para los **módulos propios**
  del usuario.
- **`clx add <spec> [--dev]`**: solo edita `cls.json` (con versión = fija; sin
  versión = rango `^<última>`, resuelto registry → global → error "no
  resuelto").
- **`clx install`** (sin args): resuelve las deps de `cls.json` y escribe
  `cls.lock`.
- Subcomandos nuevos: **`ls`**, **`info`**, **`audit`**, **`test`** (`testEntry`
  en `cls.json`: array de rutas o globs `*`/`**`/`?`).
- **Scopes anidados** (`usuario/foo@ver`) en `packages.rs` y en el resolver
  (`cls-jit/src/resolve.rs`).
- **Driver de git (`gix`)**: crate **standalone** `drivers/gix-driver` (cdylib,
  fuera del workspace para no pesar en `clx`) cargado dinámicamente
  (`libloading`, `CLS_GIX_DRIVER`). El registry **no guarda código**: publica
  `{repo, commit}` y el CLI lo baja con gix (`clx_git_abi_version` /
  `clx_git_fetch`). Build: `scripts/gix-driver-build.cmd|.sh`.
- Docs: `cli.md`/`configuracion.md`/`modulos.md`; propuestas de testing en
  `docs/lenguaje/testing.md`; plan + orden del servidor del registry en
  `agent-context/REGISTRY_PLAN.md` y `REGISTRY_SERVER_ORDER.md`.

## Feature `match` (pattern matching) + tipado estático (`Any` fuera)

### `match` (fases F1–F6)

`match` es una **expresión** (y sentencia) con 4 modos y un motor de matching
**unificado enum/clase**. Diseño completo en `agent-context/MATCH_PLAN.md`.

| Fase | Contenido |
|---|---|
| **F1** | `match` con modos `is` (tipo), `in` (valor), `if` (condición) y sin-keyword (**patrón**). Binding `nombre <- expr`; **narrowing** por arma; `default` opcional; match vacío = error; tipo = 1ª arma. |
| **F2** | **Enums con payload** (`enum R { ok(String), err(int,String), s1 }`): construcción `R::ok(...)`, patrón declarativo `ok(x)`/`err(a,b)`, **destructuring-let** `var R::ok(v) = r;`; layout heap `[def_id][idx][arity][payload…]` (los unit-only siguen empacados i64). |
| **F3** | **`?:` estilo JS** + **`if` como expresión** (`if (c) { * <- a } else { * <- b }`). |
| **F4** | **`arrowReturn` `<-`** léxico: `*`/`**` (ternario: rama de `if`-expr o cuerpo de arma de `match`) y `match`/`match*` (match por conteo); atraviesa loops; sin target = error; **sin cross-function**. |
| **F5** | **Acceso a miembro sobre unión** (dispatch por `class_id`/`def_id`); unión temporal por arma del modo `is`. |
| **F6** | **Protocolo de clases**: `__match() -> E` (namespace = variantes de `E`) + `__unpack(tag)` (payload computado); `is`/`in`(`__equals`)/`if`(`__bool`). |

Bugs corregidos al cierre (Juez): **B1** (`if`-expr anidada → WASM inválido:
emitir `unreachable` en rama divergente), **B2** (`match is`/conversiones sobre
**unión de builtins** → rechazo estático claro). Retrofit: **F-18** (armas con
`const` de distinto valor) → `Type::join_compatible` (asignable en cualquier
dirección **o** mismo tipo base, **sin ensanchar**, para no romper uniones de
literales).

### Tipado estático: `Any` eliminado

- **`Any` como anotación**: eliminado. `var x: Any` → error ("usá un tipo
  concreto o `Value`/`JSON`/`Cmx`"). Fallout migrado a `Record<String, Value>` /
  `JSON` / `Value[]` (en `.clsx`, `.clsi`, docs, grammar, tabla de tipos).
- **`Type::Any` interno**: eliminado del `enum Type` (~180 sitios). Se usa
  **`Type::Value`** como **top universal** (equivalente: assignable en ambos
  sentidos, `was_type = I64`). `TypeKind::Any` se conserva solo para dar el error
  de anotación.
- Los "dinámicos tipados" son **`Value`**, **`JSON`** y **`Cmx`** (el tag runtime
  viaja con el valor). Fixes de emisión necesarios: `toString()` sobre
  `Value`/`Json`, `length`/`size` de `JSON`.

### Retrofit de las pruebas con las features nuevas

brainfuck (`enum Op`+`match`), conformance (`match`/`?:`/`if`-expr/`<-`), clsh
(`match` sobre `enum Tok`), sqlite-orm (`match`), dns (`match`/`match is`/`<-`):
**resultados idénticos** (byte a byte). Se quitaron workarounds (`OP_*`, `K_*`,
`int(TYPE_A)`); varios *usos* de `switch` se migraron a `match` (la feature
`switch` queda intacta).

### Extensión VS Code

Fix del grammar: el patrón global `->` (return-type) se "comía" todo lo que
seguía a `->` en `match`/arrow functions. Ahora el `->` de retorno vive **solo**
en firmas de función/método; fuera, `->`/`=>` son operadores; `var-decl` acotado
a fin de línea; `::` ya no dispara la anotación `:`. Verificado tokenizando con
`vscode-textmate`.
